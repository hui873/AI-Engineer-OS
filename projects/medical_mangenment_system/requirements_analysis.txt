医疗患者信息管理系统（Python工程实践版） 项目需求分析说明书

一、项目名称 医疗患者信息管理系统

二、项目背景 医院在日常诊疗过程中需要管理大量患者基础信息。
传统人工记录方式存在查询困难、信息维护复杂、数据容易丢失等问题。
因此开发一个基于Python的患者信息管理系统，实现患者信息的规范化管理。

三、项目目标
开发一个简单、可维护、可扩展的医疗患者信息管理系统，实现： 1.
患者信息创建 2. 患者信息查询 3. 患者信息修改 4. 患者信息删除 5.
患者数据保存 6. 患者信息统计

四、用户角色分析

1.  医护人员 主要需求：

-   添加患者信息
-   查询患者信息
-   修改患者信息
-   删除患者信息
-   查看患者基本资料

五、功能需求分析

（一）患者管理功能

1.  添加患者 输入信息：

-   患者姓名
-   年龄
-   性别
-   身份证号
-   疾病信息

系统功能： 创建患者对象，并保存患者信息。

2.  查看患者信息 系统能够展示患者详细信息：

示例： 姓名：Tom 年龄：30 疾病：肺炎

3.  查询患者 支持根据以下信息查询：

-   姓名
-   身份证号

返回患者完整信息。

4.  修改患者信息 支持修改：

-   年龄
-   疾病
-   联系信息等

5.  删除患者 根据患者唯一标识删除患者数据。

（二）数据统计功能

系统支持： - 当前患者数量统计 - 平均年龄统计 - 疾病类型统计

（三）数据持久化功能

系统关闭后数据不能丢失。

采用JSON文件保存患者数据。

数据格式示例：

[ { “name”: “Tom”, “age”: 30, “disease”: “肺炎” }]

六、非功能需求

1.  可维护性 系统代码需要模块化设计，避免所有代码集中在一个文件。

2.  可扩展性 未来可以增加：

-   医生管理
-   科室管理
-   AI辅助诊断
-   医疗大模型接口

3.  代码规范 要求：

-   使用面向对象设计
-   使用类型注解
-   保持代码结构清晰

七、系统模块设计

项目结构：

medical_system/

├── main.py 程序入口

├── models/ 数据模型

    └── patient.py
    患者类

├── services/ 业务逻辑

    └── patient_service.py
    患者管理服务

├── database/ 数据存储

    └── json_db.py
    数据库操作

├── utils/ 工具模块

    └── validator.py
    数据验证

└── data/ 数据文件

    └── patients.json

八、核心类设计

1.  Patient类

职责： 描述患者对象。

属性： - name - age - gender - disease

方法： - show_info()

2.  PatientService类

职责： 处理患者业务。

方法： - add_patient() - find_patient() - update_patient() -
delete_patient()

3.  JsonDatabase类

职责： 负责数据保存和读取。

方法： - save() - load()

4.  Validator工具类

职责： 检查输入数据合法性。

九、项目开发流程

1.  需求分析 明确用户需求和系统功能。

2.  系统设计 设计模块、类和数据结构。

3.  数据设计 确定患者数据字段。

4.  编码实现 按照模块顺序开发： Patient类 → Service层 → Database层 →
    main入口

5.  测试 测试：

-   添加患者
-   查询患者
-   修改患者
-   删除患者
-   数据保存

6.  运行 执行：

python main.py

启动医疗患者信息管理系统。
