# 社区图书馆管理系统需求说明书

## 1. 项目背景

某社区图书馆需要一个简单的命令行图书管理程序，用于模拟会员登录、查看图书、借阅图书和归还图书等基本操作。

本项目主要用于练习 Python 面向对象编程，重点体现类与对象、封装、继承、多态、类方法、静态方法以及对象之间的协作。项目不以生产环境使用为目标，不要求使用数据库、Web 页面或复杂框架。

## 2. 项目目标

系统应实现以下目标：

1. 从 JSON 文件加载图书和会员数据。
2. 将每条图书记录转换为一个 `Book` 对象。
3. 将每条会员记录转换为一个普通会员或 VIP 会员对象。
4. 验证会员卡号和密码，完成会员登录。
5. 根据图书库存和会员借阅上限完成借书操作。
6. 支持会员归还自己已经借阅的图书。
7. 支持查看所有图书和当前会员的借阅情况。
8. 通过不同会员子类体现不同的借阅权限。

## 3. 项目范围

### 3.1 本项目包含

- 命令行交互界面
- 图书数据加载
- 会员数据加载
- 会员登录
- 查看全部图书
- 借阅图书
- 归还图书
- 查看当前会员的借阅列表
- 退出系统

### 3.2 本项目不包含

- 会员注册和密码修改
- 管理员功能
- 图书和会员的增删改
- 数据库
- 图形界面或 Web 页面
- 借阅期限、逾期提醒和罚款
- 多用户同时操作
- 密码加密
- 程序退出后的借阅状态持久化

程序运行期间产生的库存和借阅变化只保存在内存中。程序退出后，再次运行时重新以 JSON 文件中的数据为初始状态。

## 4. 用户角色

系统包含两种会员。

### 4.1 普通会员

- 卡号通常以 `N` 开头。
- 最多可以同时借阅 3 册图书。
- 达到 3 册后，必须先归还图书才能继续借阅。

### 4.2 VIP 会员

- 卡号通常以 `V` 开头。
- 具有 VIP 等级。
- VIP 等级为正整数，未提供时默认按 1 级处理。
- 最大借阅数量按照以下公式计算：

```text
最大借阅数量 = 6 + VIP等级
```

例如：

- VIP 1 级最多借阅 7 册。
- VIP 4 级最多借阅 10 册。
- VIP 6 级最多借阅 12 册。

## 5. 核心对象设计要求

### 5.1 Book 图书类

一个 `Book` 对象代表一种图书记录，而不是某一册具有独立编号的实体书。

图书对象应包含：

- `book_id`：图书编号
- `title`：书名
- `author`：作者
- `stock`：当前可借库存数量

图书对象应提供：

- 借出一册图书的方法
- 归还一册图书的方法
- 展示图书信息的方法
- 从字典数据创建对象的类方法
- 检查库存是否合法的方法

借出成功时，库存减少 1；归还成功时，库存增加 1。

例如，一条库存为 8 的图书记录应创建一个 `Book` 对象，并令该对象的 `stock` 为 8，而不是创建 8 个对象。

### 5.2 Member 会员基类

会员基类用于保存所有会员共有的数据和行为。

会员对象应包含：

- `card_id`：会员卡号
- `name`：会员姓名
- `password`：登录密码
- `borrowed_books`：当前已经借阅的图书列表

会员基类应提供：

- 获取最大借阅数量的方法
- 判断是否还能继续借阅的方法
- 借阅图书的方法
- 归还图书的方法
- 查看当前借阅列表的方法
- 从字典数据创建对象的类方法

### 5.3 NormalMember 普通会员类

`NormalMember` 继承 `Member`，并重写获取最大借阅数量的方法，固定返回 3。

### 5.4 VipMember VIP 会员类

`VipMember` 继承 `Member`，增加 `vip_level` 属性，并重写获取最大借阅数量的方法，返回 `6 + vip_level`。

### 5.5 LibraryService 图书管理服务类

`LibraryService` 负责协调图书对象、会员对象和当前登录状态。

服务对象应保存：

- 所有图书对象
- 所有会员对象
- 当前登录的会员对象

服务对象应提供：

- 加载图书数据
- 加载会员数据
- 会员登录
- 根据编号查找图书
- 借阅图书
- 归还图书
- 查看全部图书
- 查看当前会员的借阅列表
- 退出登录

## 6. 功能需求

### 6.1 初始化系统

程序启动后，应先创建 `LibraryService` 对象，然后加载图书和会员 JSON 文件。

每条图书数据应通过 `Book.from_dict()` 转换成一个 `Book` 对象，并保存到图书列表中。

每条会员数据应根据会员类型转换成 `NormalMember` 或 `VipMember` 对象，并保存到会员列表中。

### 6.2 会员登录

1. 系统提示用户输入会员卡号。
2. 系统提示用户输入密码。
3. 系统在会员列表中查找卡号和密码同时匹配的会员。
4. 验证成功后，将该会员对象设置为当前登录会员。
5. 验证失败时，显示“卡号或密码错误”，并结束本次运行。
6. 只有登录成功后，用户才能进入功能菜单。

### 6.3 查看所有图书

登录成功后，会员可以查看系统中的全部图书。

每条图书信息至少显示：

- 图书编号
- 书名
- 作者
- 当前库存

### 6.4 借阅图书

借阅流程如下：

1. 用户输入图书编号。
2. 系统根据编号查找对应的 `Book` 对象。
3. 如果图书不存在，显示“没有找到该图书”。
4. 系统检查当前会员是否达到最大借阅数量。
5. 如果达到上限，显示“已经达到最大借书数量”。
6. 系统检查图书库存是否大于 0。
7. 如果库存不足，显示“图书库存不足”。
8. 借阅成功时，将图书库存减少 1。
9. 将该 `Book` 对象加入当前会员的 `borrowed_books` 列表。
10. 显示借阅成功信息。

系统允许会员重复借阅同一种图书。每成功借阅一册：

- 图书库存减少 1。
- 会员借阅数量增加 1。
- 同一个 `Book` 对象可以在会员的借阅列表中出现多次，以表示借阅了多册同种图书。

重复借阅仍然必须同时满足库存充足和未达到会员借阅上限两个条件。

### 6.5 归还图书

归还流程如下：

1. 用户输入需要归还的图书编号。
2. 系统根据编号查找对应的 `Book` 对象。
3. 如果图书不存在，显示“没有找到该图书”。
4. 系统检查当前会员的借阅列表中是否存在该图书对象。
5. 如果不存在，显示“未借阅该图书”。
6. 如果存在，从借阅列表中删除一次该图书对象。
7. 将图书库存增加 1。
8. 显示归还成功信息。

如果会员借了多册同种图书，每次归还操作只归还其中一册。

### 6.6 查看我的借阅

系统应展示当前登录会员的借阅情况。

- 如果借阅列表为空，显示“当前没有借阅图书”。
- 如果借阅列表不为空，显示会员姓名以及已经借阅的图书名称。
- 如果同一种图书借阅了多册，可以重复显示该图书名称。

### 6.7 退出系统

用户选择退出后：

1. 将当前登录会员设置为空。
2. 显示“退出成功”。
3. 结束菜单循环。
4. 终止程序。

## 7. 业务规则

1. 未登录会员不能执行借书、还书和查看个人借阅操作。
2. 普通会员最多同时借阅 3 册图书。
3. VIP 会员最多同时借阅 `6 + VIP等级` 册图书。
4. 图书库存必须为大于或等于 0 的整数。
5. 只有库存大于 0 时才能借阅。
6. 每成功借阅一册，库存减少 1。
7. 每成功归还一册，库存增加 1。
8. 会员只能归还自己已经借阅的图书。
9. 允许重复借阅同一种图书，每一册分别占用一个借阅名额。
10. 借阅和归还操作只修改程序内存中的对象，不修改 JSON 文件。

## 8. 数据要求

### 8.1 图书数据格式

图书数据保存在 `data/book.json`，格式示例：

```json
[
    {
        "编号": "AI001",
        "标题": "LangChain入门与实践",
        "作者": "李智慧",
        "数量": 8
    }
]
```

字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 编号 | 字符串 | 图书的唯一编号 |
| 标题 | 字符串 | 图书名称 |
| 作者 | 字符串 | 图书作者 |
| 数量 | 整数 | 初始可借库存，不能小于 0 |

### 8.2 普通会员数据格式

```json
{
    "卡号": "N001",
    "姓名": "柳真",
    "密码": "654321"
}
```

### 8.3 VIP 会员数据格式

```json
{
    "卡号": "V001",
    "姓名": "王林",
    "密码": "666888",
    "会员等级": 6
}
```

会员数据字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 卡号 | 字符串 | 会员的唯一卡号 |
| 姓名 | 字符串 | 会员姓名 |
| 密码 | 字符串 | 登录密码 |
| 会员等级 | 整数 | VIP 专用字段，默认值为 1 |

## 9. 命令行菜单要求

会员登录成功后，系统显示以下菜单：

```text
========================
      AI图书管理系统
========================

1. 查看所有图书
2. 借阅图书
3. 归还图书
4. 查看我的借阅
5. 退出系统

========================
```

用户输入 `1` 到 `5` 执行对应功能。输入其他内容时，系统显示“输入错误，请重新选择”，然后继续显示菜单。

## 10. 面向对象设计要求

项目应体现以下面向对象思想：

### 10.1 封装

- `Book` 对象负责维护自己的库存。
- `Member` 对象负责维护自己的借阅列表。
- 外部代码通过对象方法完成借书和还书，不直接随意修改对象状态。

### 10.2 继承

- `NormalMember` 和 `VipMember` 继承 `Member`。
- 两种会员复用基类中的登录信息、借书、还书和借阅列表逻辑。

### 10.3 多态

- `NormalMember` 和 `VipMember` 分别实现自己的 `get_borrow_limit()`。
- 通用借书流程调用 `self.get_borrow_limit()`，自动根据实际会员对象使用不同规则。

### 10.4 对象协作

- `LibraryService` 查找并管理会员和图书对象。
- `Member` 对象在借书和还书过程中调用 `Book` 对象的方法。
- `main.py` 负责用户交互，不负责实现具体库存和借阅规则。

## 11. 验收标准

满足以下条件时，可以认为项目达到基本要求：

1. 使用正确卡号和密码能够登录。
2. 使用错误卡号或密码不能进入菜单。
3. 登录后能够查看所有图书。
4. 借阅成功后，图书库存减少 1，会员借阅列表增加 1 项。
5. 库存为 0 的图书不能借阅。
6. 普通会员借满 3 册后不能继续借阅。
7. VIP 会员的借阅上限等于 `6 + VIP等级`。
8. 同一会员可以在库存和借阅额度允许时重复借阅同一种图书。
9. 归还一册图书后，库存增加 1，借阅列表减少 1 项。
10. 会员不能归还自己没有借阅的图书。
11. 查看个人借阅时能够正确显示当前借阅情况。
12. 输入无效菜单编号时，程序不会退出，并提示重新选择。
13. 选择退出后，系统清除当前登录状态并正常结束。

## 12. 典型运行示例

假设普通会员 `N001` 登录，图书 `AI001` 的初始库存为 8：

```text
请输入卡号:N001
请输入密码:654321
登录成功: 柳真

请选择功能:2
请输入图书编号:AI001
柳真 借阅 LangChain入门与实践 成功
```

此时内存中的状态变化为：

```text
AI001库存：8 → 7
N001借阅数量：0 → 1
```

再次借阅 `AI001` 时，如果库存和借阅额度都足够，则仍然可以成功：

```text
AI001库存：7 → 6
N001借阅数量：1 → 2
```

归还一次 `AI001` 后：

```text
AI001库存：6 → 7
N001借阅数量：2 → 1
```

程序退出后，上述运行时变化不会写回 JSON 文件。
